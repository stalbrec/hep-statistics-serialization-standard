## Data {#sec:data}
The top-level component `data` contains an array of data sets in struct format. Each data set needs to contain the components `type` and `name`. Other components are dependent on the type of data set as demonstrated below:

-   `name`: custom string
-   `type`: string that determines the format of the observations
-   `...`: each type of observations has different parameter keys. Some of these are [optional]{.smallcaps} and marked accordingly in the more detailed description below

A detailed description of the different types with examples can be found below.
Data sets are either primary or derived:

-   *Primary data* are observations on which a distribution $p$ is evaluated, $\mathcal{L}(\theta)=p(x_\mathrm{obs};\theta)$. The types `point`, `unbinned` and `binned` describe primary data.
-   *Derived data* are the result of an earlier inference, such as unfolded spectra, measurements published with a covariance matrix or importance-sampled estimates, and carry their own statistical interpretation: a distribution $q$ belongs to the data product and is evaluated at the value of a prediction $f$, $\mathcal{L}(\theta,\nu)=q(f(\theta,\nu);\hat{\eta},\nu)$, with $\hat{\eta}$ parameters fixed by the data product and $\nu$ parameters that remain part of the model. The type `derived_data` describes derived data (see [Derived Data](#sec:derived-data)).

The uncertainty of a data product is expressed through the distribution $q$ of a derived data set. The `uncertainty` component of `point` and `binned` data and the `entries_uncertainties` component of `unbinned` data are deprecated: documents [should not]{.smallcaps} use them, and implementations [should]{.smallcaps} continue to read them.

### Axis Specifications {#sec:axes}
Axes define the observable domain for data and PDFs. Every axis is either continuous or categorical. The kind of an axis is determined structurally: an axis struct [must]{.smallcaps} contain exactly one of the field pair `min`/`max` (continuous axis) or the field `categories` (categorical axis). Continuous axes additionally have type-specific requirements based on the data type they describe.

#### Continuous Axes
A continuous axis describes a real-valued observable. All continuous axes [must]{.smallcaps} include:

-   `name`: identifier matching the observable in the PDF
-   `min`: lower bound of the observable domain
-   `max`: upper bound of the observable domain

These fields define the domain over which PDFs are normalized.

**Note on normalization**: Any PDF depending on a continuous observable $x$ must be normalized over the domain $[\text{min}, \text{max}]$ defined by that observable's axis, not over $(-\infty, \infty)$.

#### Categorical Axes
A categorical axis describes a discrete-valued observable that takes one of a finite set of named states. A categorical axis [must]{.smallcaps} include:

- `name`: identifier matching the categorical observable in the PDF
- `categories`: array of unique strings enumerating the allowed values. `categories` defines a set: the order in which values appear in the array [must not]{.smallcaps} affect evaluation.

The `categories` array itself defines the domain of the axis; the fields `min`, `max`, `nbins` and `edges` [must not]{.smallcaps} be present.  

#### Forbidden Attributes
The `const` attribute [must not]{.smallcaps} appear in axis specifications. All axes define observable domains, never fit parameters.

#### Axis Types by Data Type

**For Point Data:**  

-   Only continuous axes are permitted, carrying only the base fields (`name`, `min`, `max`) 
-   Binning fields (`nbins`, `edges`) [must not]{.smallcaps} be present

**For Unbinned Data:**  

-   Continuous axes are required to carry base fields (`name`, `min`, `max`)
-   Binning fields (`nbins`, `edges`) [must not]{.smallcaps} be present
-   Categorical axes are permitted; the corresponding column of `entries` holds the respective row's category as one of the strings listed in `categories`

**For Binned Data:**  

-   Continuous axes are required to carry base fields (`name`, `min`, `max`)
-   Each continuous axis [must]{.smallcaps} carry exactly one binning specification:
    1. Regular binning: `nbins` (integer number of equal-width bins)
    2. Irregular binning: `edges` (array of length $n+1$ bin boundaries)
-   Both `nbins` and `edges` [must not]{.smallcaps} be specified simultaneously
-   Neither `nbins` nor `edges` [must not]{.smallcaps} be omitted on a continuous axis
-   Categorical axes are permitted. A categorical axis acts as its own binning, with one bin per category in the order given by `categories`

For irregular binning, the `edges` array must satisfy:
-   `edges[0] == min`
-   `edges[-1] == max`
-   All values must be in strictly ascending order

**For Derived Data:**  

-   Continuous axes [must]{.smallcaps} carry the base fields (`name`, `min`, `max`)
-   Either every continuous axis carries exactly one binning specification (`nbins` or `edges`) as for binned data, or none does, as for unbinned data. The first form implies one support point per bin, the second lists the support points in `support_points` (see [Derived Data](#sec:derived-data))
-   Categorical axes are permitted, with the semantics of binned data in the first form and of unbinned data in the second

### Point Data
Point data describes a measurement of a single number.

-   `name`: custom string
-   `type`: `point`
-   `value`: value of this data point
-   `axes`: ([optional]{.smallcaps}) array of axis structs. Each struct must contain `name`, `min`, `max` as defined in [Axis Specifications](#sec:axes). When present, associates the point measurement with a specific observable domain.
-   `uncertainty`: ([optional]{.smallcaps}, deprecated) uncertainty of this data point; see [Derived Data](#sec:derived-data).

```json title="Example: Point Data"
"data":[
	{
		"name":"data1",
		"type":"point",
		"value":0.0,
		"axes":[
			{ "name":"obs_x", "min":-5, "max":5 }
		]
	}
]
```

### Unbinned Data
Unbinned data describes a measurement of multiple data points in a possibly multi-dimensional space of variables. These data points can be weighted.

-   `name`: custom string
-   `type`: `unbinned`
-   `entries`: array of arrays containing the coordinates/entries of the data
-   `axes`: array of axis structs. Each struct [must]{.smallcaps} be a valid continuous or categorical axis as defined in [Axis Specifications](#sec:axes). Binning fields (`nbins`, `edges`) [must not]{.smallcaps} be present.
-   `weights`: ([optional]{.smallcaps}) array of values containing the weights of the individual data points, to be used for $\chi^2$ comparisons and fits. If this component is not given, weight 1 is assumed for all data points. If given, the array needs to be of the same length as `entries`.
-   `entries_uncertainties`: ([optional]{.smallcaps}, deprecated) array of arrays containing the errors/uncertainties of each entry, of the same shape as `entries`; see [Derived Data](#sec:derived-data).

```json title="Example: Unbinned Data"
"data":[
  {
    "name":"data1",
    "type":"unbinned",
    "weights":[ 9.0, 18.4 ],
    "entries":[ [1,3], [2,9] ],
    "axes":[
      { "name":"variable1", "min":1, "max":3 },
      { "name":"variable2", "min":-10, "max":10 }
    ]
  }
]
```
Unbinned data sets with a categorical axis store the category string in the corresponding column of `entries`:
```json title="Example: Unbinned Data with categorical axis"
"data":[
  {
    "name":"data2",
    "type":"unbinned",
    "weights":[12.0, 4.3, 2.1],
    "entries":[["SR",7,0.1], ["SR",9,-0.2], ["CR",4,0.9]],
    "axes":[
      {"name":"cat1", "categories":["SR","CR"]},
      {"name":"variable1", "min":3, "max":20},
      {"name":"variable2", "min":-1, "max":1}
    ]
  }
]
```
Here the first column of `entries` refers to the `cat1` axis, giving the category of each row directly as `"SR"` or `"CR"`.

### Binned Data {#sec:binned-data}
Binned data describes a histogram of data points with bin contents in a possibly multi-dimensional space of variables. Whether entries that fall precisely on the bin boundaries are sorted into the smaller or larger bin is under the discretion of the creator of the model and thus not defined.

-   `name`: custom string
-   `type`: `binned`
-   `contents`: array of values representing the contents of the binned data set
-   `axes`: array of axis structs. Each struct [must]{.smallcaps} be a valid continuous or categorical axis as defined in [Axis Specifications](#sec:axes). Each continuous axis [must]{.smallcaps} carry exactly one binning specification:
    1.  Regular binning: `nbins` (number of equal-width bins)
    2.  Irregular binning: `edges` (array of length $n+1$ bin boundaries)
-   `uncertainty`: ([optional]{.smallcaps}, deprecated) struct representing the uncertainty of the contents; see [Derived Data](#sec:derived-data). It consists of up to three components:
    -   `type`: `gaussian_uncertainty`, the only supported kind
    -   `sigma`: array of the standard deviation of the entries in `contents`. Needs to be of the same length as `contents`
    -   `correlation`: ([optional]{.smallcaps}) array of arrays denoting the correlation between the contents in matrix format. Must be of dimension length of `contents` $\times$ length of `contents`. It can also be set to 0 to indicate no correlation.

```json title="Example: Binned Data"
"data":[
  {
    "name":"data3",
    "type":"binned",
    "contents":[ 9.0, 18.4 ],
    "axes":[ { "name":"variable1", "nbins":2, "min":1, "max":3 } ]
  },
  {
    "name":"asimov_data3",
    "type":"binned",
    "contents":[ 9.0, 18.4, 13, 0.0 ],
    "axes":[
      { "name":"variable1", "nbins":2, "min":1, "max":3 },
      { "name":"variable2", "min":0, "max":100, "edges":[0,10,100] }
    ]
  }
]
```

The `contents` of the data sets are represented in a flattened one-dimensional array of bin-contents. Here the behaviour is the same for a categorical axis with $n$ categories as for regularly-binned continuous axis with $n$ bins: each category corresponds to one bin along the respective dimension of the flattened `contents` array.

```json title="Example: Binned Data with categorical axis"
"data":[
  {
    "name":"data4",
    "type":"binned",
    "content":[9.0, 8.4, 4.0, 7.0],
    "axes":[
      {"name":"channel", "categories":["SR","CR"]},
      {"name":"variables1", "nbins":2, "min":0, "max":10}
    ]
  }
]
```

The deprecated `uncertainty` component stores pre-processed data as follows:

```json title="Example: Pre-processed binned Data (deprecated)"
"data":[
  {
    "name":"data5",
    "type":"binned",
    "contents":[ 9.0, 18.4 ],
    "uncertainty" : {
      "type": "gaussian_uncertainty",
      "correlation" : 0,
      "sigma" : [ 3, 4 ]
     },
    "axes":[
      { "name":"variable1", "nbins":2, "min":1, "max":3 }
    ]
  }
]
```

### Derived Data {#sec:derived-data}
Derived data describes a data product that is the result of an earlier inference, such as an unfolded spectrum, a measurement published with a covariance matrix or an importance-sampled estimate. Its statistical interpretation is part of the data product: a distribution $q$ defined in the top-level component `distributions` is evaluated at the value of a prediction $f$, a function defined in the top-level component `functions` and paired with the data set in a likelihood (see [Likelihoods](#sec:likelihoods)).

-   `name`: custom string
-   `type`: `derived_data`
-   `axes`: array of axis structs. Each struct [must]{.smallcaps} be a valid continuous or categorical axis as defined in [Axis Specifications](#sec:axes). The axes name the observables $x$ of the data product and define its support points $x_k$ (see below). A data set is *binned* if each of its continuous axes carries exactly one binning specification (`nbins` or `edges`) and *unbinned* if none does; a data set without continuous axes is binned.
-   `distribution`: name of the distribution $q$, defined in the top-level component `distributions`
-   `parameters`: ([optional]{.smallcaps}) array of structs with the components `name` and `value` as in [Parameter points](#sec:parameterpoints). Each entry [must]{.smallcaps} name a parameter on which $q$ depends, directly or through the functions it references, and assigns it the value $\hat{\eta}$ for the evaluation of this data set. Parameters of $q$ that are not assigned keep their ordinary semantics: they remain free or depend on other objects, and they [may]{.smallcaps} be shared with the prediction $f$.
-   `support_points`: array of arrays listing the support points $x_k$ of an unbinned data set, one inner array per support point with one value per axis in the order of `axes`. [required]{.smallcaps} for unbinned and [must not]{.smallcaps} be present for binned derived data.

The support points $x_k$ are the values of the observables at which the data set is evaluated. A binned data set has one support point per bin, located at the bin centre along each continuous axis and at the category along each categorical axis, in the order of the bins of a binned data set with the same `axes`. The support points of an unbinned data set are the rows of `support_points`.

Paired with a prediction $f$ in a likelihood, a derived data set contributes the term

$$
\begin{aligned} \mathcal{L}(\theta,\nu) &= \prod_k q\left(f(x_k;\theta,\nu);\,\hat{\eta}(x_k),\nu\right). \end{aligned}
$$

At each support point, the observables named in `axes` take the coordinates of $x_k$; $f$ and the arguments of $q$ are evaluated with these values, and the variate `x` of $q$ takes the value of $f$. Here $\theta$ are the parameters of $f$, $\hat{\eta}$ the parameters assigned by `parameters` and $\nu$ the remaining parameters of $q$, which [may]{.smallcaps} be shared with $f$. The `axes` are the observables of the data product and are distinct from the variates of $q$. Nothing is sampled: the value of $q$ at a support point is a weight that is a function of the parameters. The distribution $q$ has either a single variate or one variate per support point. In the latter case it is evaluated once, with its $k$-th variate set to $f(x_k)$, and its other arguments [must not]{.smallcaps} depend on the observables. Step functions, such as a `histfactory` function, are constant within a bin, so the position of the support point within the bin is immaterial for them.

Several derived data sets [may]{.smallcaps} reference the same distribution with different `parameters`. A measurement of two bins published with its covariance matrix is a `multivariate_normal_dist` with one variate per bin, instantiated by the data set:

```json title="Example: Derived data with a covariance matrix"
"distributions":[
  {
    "name":"xsec_dist",
    "type":"multivariate_normal_dist",
    "x":[ "xsec_bin_1", "xsec_bin_2" ],
    "mean":[ "mu_1", "mu_2" ],
    "covariances":[ [ "cov_11", "cov_12" ], [ "cov_12", "cov_22" ] ]
  }
],
"data":[
  {
    "name":"measured_xsec",
    "type":"derived_data",
    "axes":[ { "name":"pt_h", "min":0, "max":60, "edges":[0, 30, 60] } ],
    "distribution":"xsec_dist",
    "parameters":[
      { "name":"mu_1", "value":1.20 }, { "name":"mu_2", "value":0.82 },
      { "name":"cov_11", "value":0.040 }, { "name":"cov_12", "value":0.012 }, { "name":"cov_22", "value":0.025 }
    ]
  }
]
```

Paired with a prediction `xsec_prediction` in a likelihood, `xsec_bin_1` and `xsec_bin_2` take the values of `xsec_prediction` at the two bin centres, and the term is $q\left(f(15),f(45);\hat{\mu},\hat{\Sigma}\right)$. The following example represents a published measurement with statistical and systematic uncertainties and its comparison to a theory prediction.

```json title="Example: Derived data from a published measurement"
"functions":[
  {
    "name":"sherpa_prediction",
    "type":"histfactory",
    "axes":[ { "name":"p_t_j", "min":30, "max":130, "edges":[30, 50, 80, 130] } ],
    "default_interpolation":{ "type":"add", "in":"poly6", "out":"poly1" },
    "samples":[
      {
        "name":"sherpa_nlo",
        "data":{ "contents":[13.6, 6.58, 1.94] },
        "modifiers":[
          { "type":"normsys", "parameters":[ "alpha_pdf" ], "constraints":[ "alpha_pdf_constraint" ],
            "data":{ "hi":1.034, "lo":0.971 },
            "interpolation":{ "type":"mult", "in":"exp", "out":null } },
          { "type":"histosys", "parameters":[ "alpha_scale" ], "constraints":[ "alpha_scale_constraint" ],
            "data":{ "hi":{ "contents":[1.21, 0.47, 0.11] },
                     "lo":{ "contents":[-0.88, -0.36, -0.09] } } }
        ]
      }
    ]
  },
  {
    "name":"measurement_mean",
    "type":"histfactory",
    "axes":[ { "name":"p_t_j", "min":30, "max":130, "edges":[30, 50, 80, 130] } ],
    "default_interpolation":{ "type":"add", "in":"poly6", "out":"poly1" },
    "samples":[
      {
        "name":"measurement",
        "data":{ "contents":[14.2, 6.31, 1.78] },
        "modifiers":[
          { "type":"histosys", "parameters":[ "alpha_jes" ], "constraints":[ "alpha_jes_constraint" ],
            "data":{ "hi":{ "contents":[-0.63, 0.19, 0.12] },
                     "lo":{ "contents":[0.58, -0.17, -0.10] } } },
          { "type":"shapefactor",
            "parameters":[ "gamma_unfold_0", "gamma_unfold_1", "gamma_unfold_2" ],
            "constraints":[ "unfold_constraint_0", "unfold_constraint_1", "unfold_constraint_2" ] }
        ]
      }
    ]
  },
  {
    "name":"measurement_stat",
    "type":"step",
    "axes":[ { "edges":[30, 50, 80, 130] } ],
    "variables":[ "p_t_j" ],
    "parameters":[ "sigma_stat_bin_0", "sigma_stat_bin_1", "sigma_stat_bin_2" ]
  }
],
"distributions":[
  {
    "name":"measurement_dist",
    "type":"normal_dist",
    "x":"pt_spectrum",
    "mean":"measurement_mean",
    "sigma":"measurement_stat"
  },
  { "name":"alpha_pdf_constraint", "type":"gaussian_dist", "x":"alpha_pdf", "mean":0, "sigma":1 },
  { "name":"alpha_scale_constraint", "type":"gaussian_dist", "x":"alpha_scale", "mean":0, "sigma":1 },
  { "name":"alpha_jes_constraint", "type":"gaussian_dist", "x":"alpha_jes", "mean":0, "sigma":1 },
  { "name":"unfold_constraint_0", "type":"gaussian_dist", "x":"gamma_unfold_0", "mean":1, "sigma":0.015 },
  { "name":"unfold_constraint_1", "type":"gaussian_dist", "x":"gamma_unfold_1", "mean":1, "sigma":0.022 },
  { "name":"unfold_constraint_2", "type":"gaussian_dist", "x":"gamma_unfold_2", "mean":1, "sigma":0.041 }
],
"data":[
  {
    "name":"measured_pt",
    "type":"derived_data",
    "axes":[ { "name":"p_t_j", "min":30, "max":130, "edges":[30, 50, 80, 130] } ],
    "distribution":"measurement_dist",
    "parameters":[
      { "name":"sigma_stat_bin_0", "value":0.41 },
      { "name":"sigma_stat_bin_1", "value":0.27 },
      { "name":"sigma_stat_bin_2", "value":0.15 }
    ]
  }
],
"likelihoods":[
  {
    "name":"pt_likelihood",
    "predictions":[ "sherpa_prediction" ],
    "derived_data":[ "measured_pt" ]
  }
]
```

`sherpa_prediction` is a `histfactory` function, the prediction part of HistFactory without the Poisson term, with the theory nuisance parameters `alpha_pdf` as a `normsys` and `alpha_scale` as a `histosys` modifier. `measurement_mean` is the same kind of function and holds the nominal measured values with the experimental variations: the jet energy scale `alpha_jes` as a `histosys` that migrates events between bins, and the bin-wise unfolding uncertainty as a `shapefactor` with one Gaussian constraint per bin around 1. `measured_pt` is the derived data set; its distribution `measurement_dist` is a `normal_dist` around `measurement_mean` whose width `measurement_stat` is a `step` function with the statistical errors as bin values. Each number appears once: nominal values and variations in the `histfactory` functions, constraint widths in the constraint distributions, the statistical errors as parameters assigned by `measured_pt`. Prediction and data are matched through identical axes: each bin is a support point at which `pt_spectrum`, the variate of `measurement_dist`, takes the value of `sherpa_prediction`, while `measurement_mean` and `measurement_stat` take their values in that bin. The statistical errors are the Gaussian width; the systematic uncertainties are nuisance parameters of the HS$^3$ graph that can be shared with other derived data sets or with the physics model, and their constraint terms enter the likelihood through `constraints` (see [HistFactory](#sec:histfactory)). There is no `staterror`, since a Poisson constraint does not apply to unfolded bins; asymmetric statistical errors are a matter of choosing a different distribution. `default_interpolation` selects for the `histosys` modifiers the additive degree-6 polynomial interpolation within $|\alpha|<1$ with linear extrapolation outside, while the `normsys` modifier sets its own multiplicative exponential form. The `hi`/`lo` entries are the bin-wise shifts and the scale factors at $\alpha=\pm1$; an extension to further anchor points would add to this form rather than change it.
