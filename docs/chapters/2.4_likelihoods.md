## Likelihoods {#sec:likelihoods} 
The top-level component `likelihoods` contains an array of likelihoods in struct format specifying mappings of distributions and observations. The corresponding distributions and observations are inserted as keys in string format referencing to distributions and observations defined in the respective top-level components, or as numbers for fixed data values. 
A likelihood contains two kinds of terms: parameterized distributions $m_i(\theta)$ evaluated on primary data $x_i$, and the distributions $q_j$ of derived data sets evaluated at the values of predictions $f_j(\theta)$, functions defined in the top-level component `functions` (see [Derived Data](#sec:derived-data)). Together they generate the likelihood function

$$
\begin{aligned} \ensuremath{\mathscr{L}}(\theta) &=  \prod_i \text{PDF}(m_i(\theta), x_i) \prod_j q_j\left(f_j(\theta);\hat{\eta}_j,\theta\right) \end{aligned} 
$$

where $\hat{\eta}_j$ are the parameters assigned by the $j$-th derived data set and $\theta$ are all other parameters, which [may]{.smallcaps} be shared between any of the terms. Each factor of the second product, including its product over support points, is defined in [Derived Data](#sec:derived-data). The two kinds of terms differ only in where the distribution and the values at which it is evaluated originate:

| Data source  | Distribution                             | Values at which it is evaluated |
|--------------|------------------------------------------|---------------------------------|
| Primary data | `distributions`                          | `data`                          |
| Derived data | `distribution` of the `derived_data` set | `predictions`                   |

The components of a likelihood struct are: 

-   `name`: custom string 
-   `distributions`: ([optional]{.smallcaps}) array of strings referencing the considered     distributions 
-   `data`: ([optional]{.smallcaps}) array of strings referencing the used data, [must]{.smallcaps} be of the     same length as the array of `distributions`. Alternatively, the     data-values for single-dimensional distributions can be given     in-line. For example, this can be used for constraint terms     representing auxiliary measurements. 
-   `predictions`: ([optional]{.smallcaps}) array of strings referencing functions defined in the top-level component `functions`. The value of each function is the variate of the distribution of the derived data set at the same position in `derived_data`. Entries [must]{.smallcaps} be strings: a fixed number is primary data and belongs in `data`. 
-   `derived_data`: ([optional]{.smallcaps}) array of strings referencing data sets of type `derived_data` (see [Derived Data](#sec:derived-data)), of the same length as `predictions`. `predictions` and `derived_data` are paired element-wise like `distributions` and `data`. Each pair is present either completely or not at all, and a likelihood [must]{.smallcaps} contain at least one of the two pairs. 
-   `aux_distributions`: ([optional]{.smallcaps}) array of strings     referencing the considered auxiliary distributions defined in the     top-level component `distributions`. They can be used to encode     regularizers or penalty terms to aid the minimization. These     observed data for these distributions is implicit and not part of     `data`. 

A `histfactory` function referenced in `predictions` contributes the constraint terms of its modifiers to the likelihood in the same way as a distribution that depends on it (see [HistFactory](#sec:histfactory)).

```json title="Example: Likelihoods"
"likelihoods":[ 
  { 
    "name":"likelihood1", 
    "distributions":[ 
      "dist1", 
      "dist2", 
      "single_dimensional_dist_1", 
      ... 
    ], 
    "data":         [ 
      "data1", 
      "data2", 
      0, 
      ... 
    ], 
    "aux_distributions" : [ "regularization_term" ] 
  }, 
  ... 
] 
``` 

```json title="Example: Likelihood with primary and derived data"
"likelihoods":[ 
  { 
    "name":"combined_likelihood", 
    "distributions":[ "event_model" ], 
    "data":[ "observed_events" ], 
    "predictions":[ "xsec_prediction" ], 
    "derived_data":[ "measured_xsec" ] 
  } 
] 
```

Encoding of auxiliary measurements and global observables is discussed in [Auxiliary measurements](#sec:aux-measurements){reference-type="ref" reference="sec:aux-measurements"}.
